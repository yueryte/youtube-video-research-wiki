# Harness 实践：Agent 全自动知识讲解视频生成技术方案简报

本报告旨在总结如何通过 AI Agent 的工程化治理（Harness）实现从技术文章到精美知识讲解视频的全自动生产流程。该方案不依赖于传统的视频大模型，而是利用 Web 技术与 Agent 协作，确保生成过程的高度可控性与稳定性。

## 执行摘要

随着 AI 能力的增强，单纯依靠模型“抽卡”式生成视频已无法满足专业知识讲解的需求。本文档详细解析了一套基于 `Harness` 理念设计的 `Web Video Presentation` 技能（Skill）。该方案将视频制作转化为一个受控的 Web 开发工程流程，通过四个阶段（内容编写、并行开发、音频合成、录制产出）以及完善的自检机制，确保了不同主题、不同文章下视频产出的高质量与风格一致性。

---

## 核心主题深度分析

### 1. 为什么选择 Web 编码而非视频模型？
方案核心在于“可控性”。视频模型（如 Sora 等）或 NotebookLM 在处理精确演示时存在局限：
*   **高度可控：** 网页中的字体、配色、每一帧的停留时间、精确数字的出现，均可通过修改代码直接搞定，比模型随机生成更稳定。
*   **成本更低：** 网页渲染与逻辑控制的资源消耗远低于大规模视频生成。
*   **动态演示：** 相比 NotebookLM 产出的静态图，Web 框架能实现复杂的动画演示效果。

### 2. Harness 治理工程的核心：Skill 级协议
`Skill` 本质上是一份给 Agent 看的操作手册，它将复杂的生产任务转化为有流程、有状态、有检查点、有恢复机制的工程系统。

#### Agent 治理的六个维度：
*   **上下文管理：** 将文档拆分为多份（如口播规范、开发指引等），仅在特定阶段读取，避免模型注意力被稀释。
*   **执行与编排：** 将流程切割为四个阶段，并在关键点设置人工检查点（Human-in-the-loop）。
*   **状态与记忆：** 通过 `outline.md`（开发计划）固定关键决定，使其成为跨步骤的持续记忆，确保画风和逻辑的连续性。
*   **工具系统：** 充分利用 Agent 自带的文件读写工具及外部 CLI（如 MiniMax TTS）。
*   **评估与观测：** 建立硬性自检规则，甚至引入独立的 `Reviewer Agent` 逐项核查。
*   **约束与恢复：** 遵循“最小切片修复”原则，针对具体反馈（如节奏太快）仅修改最小代码单元，避免重作整个章节导致其他部分劣化。

### 3. 全自动视频生产的四个阶段

| 阶段 | 核心产出 | 关键逻辑 |
| :--- | :--- | :--- |
| **阶段一：内容编写** | 口播稿、开发计划 | 将文章口语化（第二人称、短句）；拆分细粒度章节与视觉步骤。 |
| **阶段二：网页开发** | HTML/CSS/JS 代码 | 逐章开发，支持多 Agent 并行。第一章作为基准（Baseline）需人工验收。 |
| **阶段三：音频合成** | 批量语音文件 | 调用 TTS 能力，根据口播稿自动生成与步骤对应音轨。 |
| **阶段四：视频录制** | 录屏成品 | 网页支持手动、半自动、全自动（自动对齐音频节奏）三种播放模式。 |

## 关键引述与背景

> **“答案就两个字：可控。字体、配色、每步停几秒……这些东西在网页里改几行代码就可以直接搞定，比用视频模型直接抽卡要稳定得多。”**
*   **背景：** 解释为何在视频模型强大的今天，依然选择“折腾网页”。

> **“Skill 本身就是一份给 Agent 看的操作手册，它告诉 Agent 什么时候该做什么、做到什么标准、哪些红线不能碰。”**
*   **背景：** 定义了 Harness 在 Skill 级别的具体实现意义。

> **“Harness 最核心的价值，就是把模型能力、工具能力和人的判断组织成一条稳定可控的生产流程。”**
*   **背景：** 对整套自动化体系哲学观的总结。

## 核心工具栈

*   **执行 Agent:** `Claude Code` (核心执行器，亦可适配 Cursor/Codex)。
*   **推理模型:** `MiniMax 2.7` (推荐搭配使用，Token Plan 适配性高且包含多模态能力)。
*   **配置工具:** `cc-switch` (用于将 Claude Code 等 Agent 切换至国内模型)。
*   **音频能力:** `MiniMax CLI` (实现口播稿的自动语音合成)。
*   **多 Agent 管理:** `tmux` (配合 Agent Teams 模式，可视化监控多个 Agent 的并行开发状态)。

## 行动指南与实战建议

### 1. 环境初始化
1.  安装 `Claude Code` 并确保版本正常。
2.  通过 `cc-switch` 配置 `MiniMax` 模型，利用其高性价比的 Token 套餐。
3.  安装 `MiniMax CLI` 并配置 API Key，用于后续音频生成。
4.  从 `Garden Skills` 仓库下载 `web-video-presentation` 技能包。

### 2. 生产策略选择
在进入开发阶段时，根据项目规模选择 Agent 模式：
*   **Subagent 模式：** 适合结果导向任务，如并行开发多个章节，节省 Token 且易于调度。
*   **Agent Teams 模式：** 适合需要来回反馈的任务，如“开发-测试-复查”循环。需在配置中启用实验性功能并配合 `tmux` 使用。

### 3. 验收关键点
*   **第一章基准点：** 在并行开发所有章节前，必须确保第一章的视觉气质、信息密度和动效节奏完全符合预期。
*   **自检流程：** 严禁 Agent “目测”通过，必须要求其对照 Checklist 逐项核查代码结构与内容对齐。
*   **录制模式：** 最终录制时，建议添加 `auto=1` 参数进入全自动播放模式，按空格键即可实现音画同步自动演示。
