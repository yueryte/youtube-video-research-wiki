# Solo vs F-Harness：单模型与多智能体成本质量对比

## 概述

在 [[Harness Engineering]] 的实践中，一个核心决策点是：**究竟应该让一个强大的单模型独立完成任务（Solo 模式），还是构建一个多智能体协作系统（F-Harness 模式）？** 本页面基于 Anthropic 的公开实验数据与 OpenAI 的生产实践，从成本、质量、时间三个维度进行系统对比。

## 核心实验数据

### Anthropic 长程任务对比实验

Anthropic 针对复杂软件开发任务，设计了一组严格的对照实验：

| 维度 | Solo（单模型） | F-Harness（多智能体） |
|:---|:---|:---|
| **耗时** | 20 分钟 | 6 小时 |
| **成本** | 9 美元 | 200 美元 |
| **产出质量** | 基本不可用 | 达到可商用高水准 |
| **架构复杂度** | 无 | 三角色协作系统 |
| **人工干预需求** | 频繁 | 极少 |

### OpenAI 百万行代码实验

OpenAI 在 2024 年的生产系统开发实验中，虽然没有直接对比 Solo 与 F-Harness，但其采用的 [[Harness 优化策略]] 本质上是一种轻量级的多智能体协作：

- **开发周期：** 5 个月生成约 100 万行代码
- **效率提升：** 纯人工的 10 倍
- **关键机制：** 验证反馈闭环、自动自愈、技术债清理 Agent

## 架构对比

### Solo 模式

**特点：**
- 单一模型实例独立完成所有任务
- 无角色分工，模型自行规划、执行、验证
- 依赖模型自身的全局统筹能力

**适用场景：**
- 任务复杂度低、范围明确
- 对质量要求不苛刻
- 成本敏感型场景

### F-Harness 模式

**核心架构（三角色协作）：**

1. **Planner（规划者）**
   - 将模糊需求拆解为详细功能点列表
   - 制定执行路线图
   - 与 Generator 讨论交付标准

2. **Generator（生成者）**
   - 按列表逐一实现功能
   - 与 Evaluator 保持沟通
   - 根据反馈迭代修改

3. **Evaluator（评估者）**
   - 独立第三方 Agent
   - 客观检查产出质量
   - 避免“自卖自夸”导致的 Bug 遗漏

**适用场景：**
- 长耗时、高复杂度任务
- 质量要求严格（如生产系统）
- 需要持续迭代和验证

## 成本质量权衡

### 成本分析

| 成本类型 | Solo | F-Harness |
|:---|:---|:---|
| **Token 消耗** | 低（单次调用） | 高（多轮对话+角色切换） |
| **API 调用次数** | 少 | 多（3 倍以上） |
| **人工成本** | 高（频繁干预） | 低（自动化闭环） |
| **总成本** | 9 美元/任务 | 200 美元/任务 |

### 质量分析

| 质量维度 | Solo | F-Harness |
|:---|:---|:---|
| **代码正确性** | 低（常有幻觉） | 高（多重验证） |
| **系统稳定性** | 差 | 好（自愈机制） |
| **可维护性** | 差 | 好（结构化产出） |
| **可复用性** | 低 | 高（模块化设计） |

## 关键洞察

### 1. 质量拐点效应

实验数据表明，Solo 模式存在明显的 **质量拐点**：当任务复杂度超过某个阈值后，单模型的表现会急剧下降。F-Harness 通过角色分离和独立验证，有效突破了这一瓶颈。

### 2. 成本效率悖论

虽然 F-Harness 的绝对成本是 Solo 的 22 倍，但考虑到产出质量从“不可用”提升到“可商用”，**单位有效产出的实际成本反而更低**。对于生产级系统，F-Harness 是更经济的选择。

### 3. 模型能力的“吸收”效应

值得注意的是，随着模型能力的提升（如从 Claude 3.5 到 3.6），原本需要 F-Harness 才能完成的任务，Solo 模式可能逐渐胜任。这符合 [[模型能力吸收效应]] 的规律：**模型越强，所需的 Harness 越少**。

## 决策框架

### 选择 Solo 模式的条件

- 任务可在 30 分钟内完成
- 产出质量要求为“可用即可”
- 预算有限（< 50 美元/任务）
- 有充足的人工审查资源

### 选择 F-Harness 模式的条件

- 任务耗时超过 1 小时
- 产出需要达到生产级质量
- 预算充足（可接受 200+ 美元/任务）
- 追求自动化闭环，减少人工干预

## 未来趋势

1. **混合模式兴起：** 结合 Solo 的快速响应与 F-Harness 的质量保障，形成动态切换机制
2. **成本下降曲线：** 随着模型效率提升和 API 降价，F-Harness 的成本优势将更加明显
3. **角色专业化：** 出现专门针对 Planner、Generator、Evaluator 的优化模型
