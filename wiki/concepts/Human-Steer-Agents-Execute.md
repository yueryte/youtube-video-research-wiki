# Human Steer Agents Execute

## 概念定义

**Human Steer Agents Execute**（人类掌舵，Agent 执行）是 [[Harness Engineering]] 领域的核心理念，由 OpenAI 在其大规模 AI 驱动开发实践中正式提出。该理念重新定义了 AI 时代软件工程师的角色定位：人类工程师不再是一行行编写代码的执行者，而是转变为制定规则、提供上下文、在关键节点做出判断的“掌舵者”，而具体的代码生成、测试执行、Bug 修复等重复性工作则交由 AI Agent 完成。

这一理念的核心公式可表达为：
> **Human = Steer（方向与决策）**  
> **Agent = Execute（执行与产出）**

## 技术背景与起源

该理念源于 OpenAI 在 2024 年启动的一项极端实验：利用 AI 从零开始编写一个真实的线上生产系统。实验取得了惊人的成果——5 个月内生成约 100 万行代码，开发效率提升至纯人工的 10 倍。在总结这一实践时，OpenAI 提出了两个具有灵魂意义的观点：

1. **"Human Steer, Agents Execute"** —— 人类工程师的角色从代码编写者转变为系统架构师。
2. **工程师的新职责** —— 软件工程并没有消失，而是演变为“为 Agent 搭建稳定可靠的系统与支撑框架”，以最大化代码产出效率。

## 核心理念解析

### 1. 掌舵（Steer）的具体内涵

人类掌舵并非简单的“审批”或“监督”，而是包含以下具体技术动作：

- **上下文架构设计**：放弃“大而全”的单一 `agent.md` 文档，改为目录化结构，仅在需要时按需加载相关规范。这避免了模型在长文本中迷失，属于 [[Context Engineering]] 的高级实践。
- **唯一事实来源建立**：强制将 Slack 记录、Google Doc 等碎片信息迁入代码仓库，确保 Agent 能感知仓库外的决策背景。
- **验证闭环设计**：为 Agent 配置 Chrome DevTools 截图验证 UI，并引入 Lint 和自动化测试。如果代码报错，错误信息会返回给 Agent 进行自愈式修复，无需人工干预。
- **技术债管理**：设置后台定时任务，由 Agent 自动扫描代码库和文档，清理不一致的命名或过时的文档。

### 2. 执行（Execute）的自主边界

Agent 的执行并非完全无监督，而是在人类设计的 Harness 框架内自主运作。Anthropic 的 [[F-Harness 架构]] 提供了典型的多智能体协作模式：

- **Planner（规划者）**：将模糊的需求拆解为详细的功能点列表。
- **Generator（生成者）**：按照列表逐一实现功能，并与评估者讨论交付标准。
- **Evaluator（评估者）**：独立的第三方 Agent，负责客观检查产出，避免“自卖自夸”导致的 Bug 遗漏。

实验数据显示，Solo（单模型）方案耗时 20 分钟、成本 9 美元，但产品基本不可用；F-Harness 方案耗时 6 小时、成本 200 美元，但产出达到了可商用的高水准。这一对比清晰地展示了“人类掌舵”的价值——虽然成本更高，但产出的质量与稳定性远超无监督的单一模型模式。

## 争议与边界

### 争议点：人类角色的弱化风险

批评者认为，该理念可能过度理想化人类与 Agent 的分工。在实际应用中，当 Agent 执行出现偏差时，人类掌舵者往往需要深入理解 Agent 的行为逻辑才能有效干预，这对工程师的能力提出了更高要求。

### 边界条件：模型能力的演进

一个非常现实的趋势是：**模型越强，所需的掌舵干预就越少**。当模型从 Claude 3.5 升级到 3.6（Opus 系列）后，原本为了解决“上下文焦虑”而设计的重置技术变得不再必要；原本需要强行干预的“逐个功能点执行”流程，也被模型更强的全局统筹能力所取代。这意味着 Human Steer Agents Execute 可能是一个过渡性理念，随着模型能力的提升，人类的掌舵角色可能进一步向更高层次的战略决策演进。

## 实践建议

1. **明确掌舵边界**：定义哪些决策必须由人类做出（如架构选型、安全策略），哪些可以完全交给 Agent（如代码实现、测试生成）。
2. **建立反馈闭环**：设计自动化的验证机制，确保 Agent 的执行结果可审计、可回滚。
3. **持续优化 Harness**：根据模型能力的演进，动态调整掌舵的粒度与频率。
