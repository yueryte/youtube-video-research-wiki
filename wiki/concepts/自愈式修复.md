# 自愈式修复

**自愈式修复**是 [[Harness Engineering]] 中的一项关键技术，指 Agent 在检测到代码错误后，无需人工介入，自动获取错误信息、分析根因、生成修复代码并重新验证的闭环过程。该机制是构建长期稳定运行的 [[Agent]] 系统的核心能力之一。

## 技术原理

自愈式修复的实现依赖于一个完整的反馈闭环：

1. **错误检测**：Agent 在执行代码后，通过集成 Lint 工具、自动化测试套件或运行时日志捕获错误。例如，在 OpenAI 的实验中，Agent 被配置为在每次代码变更后自动运行 Chrome DevTools 进行 UI 截图验证，并与预期状态对比。
2. **信息回传**：捕获的错误信息（包括堆栈跟踪、错误类型、失败测试用例等）被结构化为上下文，直接回传给 Agent 的 LLM 核心。
3. **根因分析**：Agent 基于回传的错误信息，结合代码库的上下文（如相关函数定义、依赖关系），自主推断错误的根本原因。
4. **修复生成**：根据分析结果，Agent 生成修复代码，并可能涉及修改多个文件或调整配置。
5. **重新验证**：修复后的代码再次经过相同的检测流程，确保错误被彻底解决，且不引入新的回归问题。

## 实战案例：OpenAI 的百万行代码实验

在 OpenAI 的实验中，自愈式修复是其实现“5 个月内生成 100 万行代码”的关键支柱。当 Agent 编写的代码在 Lint 检查或自动化测试中失败时，错误信息会直接返回给 Agent 进行自愈。这一过程完全自动化，无需人工工程师介入，极大地提升了开发效率。报告指出，这种机制使得 Agent 能够处理大量“试错-修复”循环，而人类工程师只需在关键节点进行决策。

## 与 [[上下文工程]] 的关系

自愈式修复的有效性高度依赖于 [[上下文工程]] 的质量。Agent 需要能够准确获取与错误相关的上下文信息（如相关代码片段、依赖库版本、设计规范），才能进行有效的根因分析。如果上下文不足或错误，自愈过程可能会产生错误的修复，甚至引入新的问题。

## 价值与挑战

- **价值**：显著降低人工运维成本，加速开发迭代，使 Agent 能够处理大规模、长周期的任务。
- **挑战**：自愈式修复可能增加计算成本（如 Anthropic 的 F-Harness 实验所示），且对于复杂的、涉及架构设计的错误，Agent 可能无法独立解决，需要人工介入。此外，过度依赖自愈可能导致技术债的积累，需要配合 [[技术债清理]] 机制使用。
