# 唯一事实来源

## 定义

**唯一事实来源**（Single Source of Truth, SSOT）是 [[Harness Engineering]] 体系中的一项核心上下文管理策略。其核心理念是：**将所有与项目决策相关的碎片化信息（如即时通讯记录、临时文档、会议纪要等）强制迁移并集中存储在一个统一的、可被 Agent 感知的仓库中**，从而消除信息孤岛，确保 AI Agent 在执行任务时能够获取完整、一致且最新的决策上下文。

## 背景与动机

在 OpenAI 的 100 万行代码实验中，工程师发现了一个关键瓶颈：当项目信息分散在 Slack 讨论、Google Doc 草稿、本地笔记等多个渠道时，AI Agent 无法感知这些“仓库外”的决策背景。这导致 Agent 生成的代码虽然语法正确，但往往与团队最新的架构决策或业务逻辑相悖。

例如，一个在 Slack 上讨论并决定弃用的 API 接口，由于未及时更新到代码仓库的文档中，Agent 可能会继续基于旧接口生成代码，造成大量返工。**唯一事实来源**正是为了解决这一“上下文断层”问题而提出的强制性策略。

## 核心实践

### 1. 信息迁移与归集
- **强制迁移**：将 Slack 讨论、Google Doc、Notion 笔记等所有与项目相关的决策记录，统一迁移至代码仓库的指定目录（如 `/docs/decisions/` 或 `/adr/`）。
- **格式标准化**：所有迁移的信息需遵循统一的 Markdown 模板，包含决策日期、参与者、背景、结论及替代方案。
- **废弃与清理**：原渠道中的信息在迁移后应标记为“已归档”或直接删除，避免 Agent 通过其他途径获取过时信息。

### 2. 按需加载的目录化结构
- 避免将所有上下文塞入一个巨大的 `agent.md` 文件（这会导致模型在长文本中“迷失”）。
- 采用目录化结构，将上下文按模块、功能或决策类型拆分。Agent 仅在需要时通过工具调用按需加载相关文件。
- 例如：`/docs/decisions/api-design.md`、`/docs/decisions/database-schema.md`、`/docs/decisions/deployment-strategy.md`。

### 3. 自动化同步与校验
- 设置后台定时任务（Cron Job），由 Agent 自动扫描代码仓库和文档目录。
- 自动检测并清理不一致的命名、过时的文档引用或与当前代码状态不符的决策记录。
- 将清理结果作为反馈闭环的一部分，通知人类工程师进行最终确认。

## 与 [[上下文工程]] 的关系

唯一事实来源是 [[上下文工程]] 在实践层面的具体落地策略之一。上下文工程关注的是“在合适的时间将合适的信息放入 Context”，而唯一事实来源则确保了“这些信息本身是正确、完整且唯一的”。没有 SSOT，上下文工程将沦为“从错误源头获取错误信息”的无效工程。

## 与 [[知识图谱]] 的协同

在更宏观的 [[知识图谱]] 体系中，唯一事实来源扮演着“事实锚点”的角色。每个知识节点（如一个技术决策、一个 API 规范）都应当能够回溯到其在 SSOT 仓库中的原始记录。这种可审计性使得知识图谱不再是空中楼阁，而是扎根于可验证的原始事实之上。

## 争议与局限

- **维护成本**：强制迁移所有碎片信息需要额外的人力投入，尤其在快速迭代的团队中，容易成为流程负担。
- **模型能力演进**：随着模型上下文窗口的扩大和检索能力的增强，未来模型可能直接从 Slack、Google Doc 等原始渠道中准确提取信息，届时 SSOT 的强制性可能降低。但至少在目前，它仍是确保 Agent 输出可靠性的最现实手段。

## 总结

唯一事实来源不是一种技术工具，而是一种**组织纪律**。它要求团队将“信息集中化”视为与“代码版本控制”同等重要的基础设施。在 [[AI Agent 时代]]，它决定了 Agent 能否从“玩具”进化为“生产力工具”。
